## Portable production contract

`scripts/data/pihc2_entity_contract.yaml` is 1,310,855 bytes and 2,200 lines with one terminal newline. Its Heaven SHA-256 is `86bff3664ca0e589ef0daf22af9025c0bb97abe7f1c9bd86470c17b5bf675744`.

The contract pins every source and compiled relative path, byte size, and SHA-256. It embeds canonical UTF-8/base64 evidence for 140 inputs whose exact bytes cannot be recovered from the compiled copy set: 134 `info.json` files, `entities.json`, and five raw `animations.asset` files that differ from generated declarations. Those decoded payloads total 898,601 bytes. The remaining 173 raw source files are each reconstructible from a checked compiled static asset with the same byte size and SHA-256.

An inventory review caught eight `.DS_Store` files before the first contract was accepted. Contract paths now reject every dot-prefixed path component, source discovery excludes hidden metadata only after rejecting symlinks, and focused coverage prevents hidden files from re-entering the contract or import snapshot.

## Strict semantics and transaction safety

Preflight requires the exact 6/312/134 source inventory, table bytes, 9 PDX inputs, 173 static inputs, and 184-file output. It rejects missing, extra, duplicate, corrupt, path-unsafe, or symlinked inputs. JSON and YAML contracts reject duplicate keys. Every PDX entry must use the assignment operator and retain its checked scalar type, nesting, record counts, names, mesh references, clone references, and animation shape.

All source bytes are captured into one immutable prepared snapshot before staging. Staging occurs beside the destination and is byte-compared against that snapshot before installation. `--clean` affects only modules carrying the exact `compiled-entities` owner tag; template-created and other unowned modules are preserved.

Normal `Exception`, `KeyboardInterrupt`, and `SystemExit` install failures restore the prior module and the destination root's original existence state. If rollback itself fails, `IncompleteMigrationRollbackError` reports the incomplete recovery and retains staged/backup transaction evidence for manual restoration rather than silently discarding it.

## Novice entity creation

The old `pihc3:entity/basic` template wrote `mesh.gfx` and `entity.asset` at module root, but the family accepted only `gfx/models/**`. The GUI/SDK could therefore create a module that had no required PDX source and could not build.

The starter now writes:

```text
src/modules/entity/<OBJECT_ID>/gfx/models/<OBJECT_ID>/mesh.gfx
src/modules/entity/<OBJECT_ID>/gfx/models/<OBJECT_ID>/entity.asset
```

The normal `Project.create_module("entity", ...)` shorthand resolves to this template. Acceptance creates a fresh module in a temporary project, checks the compact catalog metadata and source-slot plan, performs strict discovery, and builds exactly the two documented owner artifacts. The starter is an editable definition shell; the author must still supply the referenced `.mesh`, texture, and optional animation files before the model can render in-game.

## Source bytes versus emitted PDX formatting

Independent review found an important documentation/test gap: the checked module and importer preserve all 182 compiled input files exactly, but ParaDev intentionally parses and canonically serializes files in a `pdx` slot at build time. Eight of the nine PDX output byte hashes therefore change through whitespace/formatting; the zero-byte rifle declaration remains unchanged.

This is not a semantic change. A new emitted-build contract recursively compares every ordered key, operator, scalar type/value, nested block, and record across all 9 source and emitted PDX trees. All match exactly. It also writes and byte-compares all 173 static outputs. The bilingual manual and migration notes now distinguish byte-exact checked/imported sources, byte-exact emitted static assets, and structurally identical canonical PDX output.
