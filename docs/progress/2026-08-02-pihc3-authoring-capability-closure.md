# PIHC3 Authoring Capability Closure

Date: 2026-08-02

## Outcome

PIHC3's full visible authoring catalog is now verified through the same
HeavenBase 0.1.2.1 Registry projection used by ParaDev's SDK, desktop, REST,
MCP, and agent surfaces. The project currently publishes 51 visible module
families and 52 create templates. Every visible family has a template and at
least one editable resource slot; every localization-requiring template creates
a localization source; and every visible copy/image slot has a safe
module-relative authoring destination.

Focus, Technology, Doctrine, and Military Industrial Organization publish the
four Registry-owned editable diagram providers. `equipment_module_category` is
the intentional localization/image-only family; the other 50 visible families
also expose guided PDX or project-defined source forms.

This closes the generic capability gap without adding a PIHC3 family switch to
ParaDev. Extension Entities and templates remain the semantic owners.

## Agent and GUI parity

The desktop AI template catalog now consumes the exact same `form.fields`
projection as the GUI create dialog rather than reconstructing fields from the
lower-level template argument list. It validates that the two field-name sets
match and fails closed on a divergent extension contract.

As a result, all 391 current template fields have the same readable label in
the GUI and AI prompt, including labels generated by the SDK when an extension
does not provide one explicitly. Field types, required flags, defaults,
advanced status, choices, and extension-authored descriptions pass through the
same projection. Twenty-eight fields currently have explicit semantic
descriptions; extending authoritative descriptions for the remaining advanced
fields is follow-up extension work, not a host-side lookup table.

Decision, Event, and Idea now explicitly declare their localization resources
as `kind="loc"`. Their hidden extension bundle versions advance from 0.2.3 to
0.2.4, keeping Registry cache invalidation deterministic. The real
`Project.browser(...)` path resolves those slots for 458 Decision modules,
41 Event modules, and 390 Idea modules.
