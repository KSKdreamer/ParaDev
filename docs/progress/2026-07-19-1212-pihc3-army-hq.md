# PIHC3 Army HQ and importer-safety checkpoint

## Outcome

PIHC3 now restores the current HOI4 1.19.2 Army Headquarters contract that its broad replacement paths previously hid. The unit definitions, generic history template, and AI template are native, editable PIHC3 modules with novice-readable metadata and exact startup/build contracts. PIHC2 unit/history regeneration is also transactional: invalid inputs and collisions are rejected before mutation, interruptions roll back, and incomplete recovery state is retained for inspection.

The PIHC changes are published in draft [HOI4-PIHC PR #2](https://github.com/Magolor/HOI4-PIHC/pull/2) at commit `2a9a989763fb9a2ada41db130f6f97fd2177dfe5`. The user's original PIHC3 checkout remains untouched.

## Current-game Army HQ compatibility

Three hand-maintained modules close the replacement-path boundary:

- `UNIT_COMPONENT_UNITS_HQ_SUPPORT` emits `common/units/hq_support.txt` with the closed base graph `hq_infantry` and `hq_support_company`.
- `HISTORY_COMPONENT_GENERAL_TAOG_HQ_TEMPLATE` emits the generic `history/general/taog_hq_template.txt` fallback.
- `AI_COMPONENT_AI_TEMPLATES_HQ_SUPPORT` emits `common/ai_templates/hq_support.txt` with `role = hq_role` and the same compact target composition.

The default template contains two `hq_infantry` regiments and one `hq_support_company`. Its PIHC-scale total is 48 manpower and 96 `ARCHETYPE_INFANTRY`, one sixth of the common nine-battalion PIHC infantry division. Metadata exposes the DLC, upstream version/path, emitted path, role, composition, per-subunit manpower/equipment, template totals, and reason for the compatibility override so a novice can understand the module in the generic editor.

Specialist vanilla HQ progression remains intentionally out of scope because PIHC replaces the technologies and abilities it references. Importing the entire upstream file would create dangling dependencies.

## Transactional PIHC2 entity regeneration

The unit and general-history importers now:

- preflight their exact 25-file and 30-file source manifests before any destination mutation;
- stage complete replacement trees in a hidden same-filesystem transaction directory;
- reject a symlink anywhere in destination ancestry, symlinked module/metadata roots, and same-ID unowned collisions;
- remove only modules carrying the importer-specific owner tag when `--clean` is requested;
- pre-register every destructive rename, install the staged set as one transaction, and restore the prior set after ordinary errors, `SystemExit`, or `KeyboardInterrupt`;
- retain the transaction directory and aggregate recovery errors whenever rollback is incomplete, including the no-prior-backup case.

The compatibility HQ modules have different ownership tags and remain byte-identical across clean legacy regeneration.

## ParaDev standard-gate coverage

The importer-safety bridge was moved out of the historical slow migration-contract module, so `scripts/test.bash` collects it in the default fast gate. Because PIHC is a separate private repository and is intentionally absent from a clean ParaDev checkout, the ParaDev branch carries a minimal text-only fixture pinned to PIHC commit `2a9a989763fb9a2ada41db130f6f97fd2177dfe5`. It contains only the transaction helper, two production importers and their dependency, the exact nested safety suite, and the two compatibility modules.

This avoids both an undeclared cross-repository credential and a roughly two-gigabyte checkout in every Python matrix job. When `PARADEV_PIHC3_ROOT` is explicit, the gate compares every pinned file byte for byte against the live checkout before accepting it.

Verification results:

- 30 PIHC script tests passed in 0.71 seconds;
- the four focused ParaDev migration/startup/cache/source-root contracts passed in 85.70 seconds;
- the pinned-fixture gate passed from both fixture and live PIHC roots;
- the exact default ParaDev fast gate passed 1,452 tests and deselected 316 slow tests;
- scoped Black, Flake8, and `git diff --check` passed;
- independent final review found no remaining P0-P2 issue.

The default gate took 24 minutes 49 seconds. Several unmarked integration cases advanced at roughly 30-second intervals, so the suite is correct but not yet providing fast packaging feedback. Test duration classification and timeout ownership are a separate follow-up.

The Heaven-style scanner's only notices on the six PIHC migration/checker files are their intentional typed `pathlib` imports. Production file operations and serialization use HeavenBase helpers.
